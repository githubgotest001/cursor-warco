# 字段规范 与 正史 / 野史文风范例

写档案前读这份。上半是字段的精确规范，下半是语感校准用的真实范例——照着范例的「节奏」写，比记规则更快。

> **文风版本说明**：2026-08-28 起全站定稿双线异体——**正史 = 杂志特稿体，野史 = 红后终端体**。库内 84 条已按此风格全量重写，新档案必须与之一致。

## 一、字段逐条规范

### side
- `main` = 正史（官方档案，脊柱之左）
- `dark` = 野史（场外情报，脊柱之右）
- 只有这两个值，服务端会校验。

### date
- 格式严格 `YYYY-MM-DD`，到日。
- 记**事件发生 / 官宣的那天**，不是写作当天。官宣日以官方口径为准（注意时区：美国时间的官宣，国内看到可能已是次日凌晨——两者都可，同一网站内部保持一致即可）。

### tag（2–4 字中文，给卡片一个「事件性质」标记）
现用词库，可沿用也可按需新拟，但保持简短、有性格：

- **正史常用**：起源、首发、融资、并购、里程碑、发布、整合、纪元、惊变、军备、登顶、夺榜、故障、动荡、结盟、上市、变阵、破壁、进化、平价、平替、反攻、进场、双子、首秀、断供
- **野史常用**：冷眼、破防、造词、罢工、事故、**套利、重套利、极限套利**（按玩法量级分级）、**灭活**、众怒、谍战、删库、围城、玩梗、扒皮、漏洞、情报、封锁

### title（≤ 20 个中文字，英文按半宽算）
- **信息优先**：标题在三个地方独立出现——时间轴卡片、详情页「事件线索」列表、RSS/搜索结果。线索列表里**只有日期和标题**，所以标题必须自己把关键信息带上（主体、数字、结果），不能依赖摘要补全。
- 正史（特稿体）：冷名词句或「主题：信息」结构，数字入题。
  - 好：`600 亿美元：全股票收购签约`、`Composer 2.5：便宜一个量级`、`D 轮 23 亿，NVIDIA 入局`
  - 差：`Cursor 完成新一轮融资`（无信息量）、`惊天巨变！`（喊）
- 野史（红后体）：冷句 +「取证 / 观测 / 判定」气质，信息照样要满。
  - 好：`舆情采样：不就是个套壳吗`、`客服单元 Sam：政策系幻觉`、`账单数据：份额 41% 滑至 26%`
- **检出 / 灭活对**有专用格式，见「四、事件线索」。

### summary
- **一段**连续文字，约 60–90 字（含英文可到 ~120 字符），时间轴卡片直接显示。
- 卡片上方已有日期与 tag，摘要**不要**重复「X 月 X 日」开头浪费字数（正史可少量保留以叙事，野史一律省）。
- 正史：浓缩「发生了什么 + 为什么值得记」，收在一个冷静的观察上。
- 野史：字段化短句拼装，见下方红后体模板。

### detail
- 调阅档案时的详情，**空行分段**（`\n\n`），2–4 段。
- 正史（特稿体）典型三段：① 事件经过（含查证到的事实与数字）② 背景 / 机制 / 各方反应 ③ 时间跨度上的呼应或冷收束。
- 野史（红后体）固定三段，见模板。

### image
- 可空，**默认留空**。图片由用户自行提供（本 skill 不生成、不找图）；如用户给了就填 `/uploads/文件名.png` 或外链 URL。

### series（事件线索名，可空）
- 同一条故事线的多条档案填**同一个** series 字符串，前台自动串联：卡片出现可点的 🔗 线索徽标，详情页「事件线索」列出全部节点（带超链接）并计算窗口跨度。
- 现役线索：`融资阶梯`、`模型军备`、`自研模型线`、`火箭并购案`、`定价攻防`、`AI 失控档案`、`供给线`，以及检出/灭活成对线索（`临期锁额`、`Team 席位差`、`假焚诀`）。
- 新开线索的门槛：**已经或可预期有 ≥2 条档案**。孤条不挂线索。

### source
- 可空。填一条最硬的 URL（官方博客 / SEC / 权威媒体 / 论坛官方帖）。

### 术语纪律（全站统一的「记录者口音」）

原则一句话：**记录者的叙述词汇用冷的情报术语；被记录对象的黑话保留，但一律加「」降格为语言样本。** 清冷、客观、低调是全站底色，市井口音只能以「证物」形态出现。

| 市井词（禁用于叙述） | 记录者用词 |
| --- | --- |
| 民间、街面 | 场外 |
| 群聊、微信群 / QQ 群、技术群 | 封闭频道 |
| 圈内、圈里 | 情报网内 |
| 中文圈 | 中文区 |
| 爆料 | 线报 |
| 羊毛党、白嫖党 | 套利者 |
| 薅羊毛、白嫖（作叙述动词时） | 套利 |
| 二手号市场、二手平台 | 场外市场 / 场外平台 |
| 发糖 | 补给 / 放闸 |
| 社区传闻 | 未具名信源 |

黑话入档必须带「」并尽量交代出处，例：`「车头」批量注册发车`、`场外命名为「额度锁定」`、`官方口中的「Bot 回血」`。俗语可作引语保留：`场外结案词早有现成的——「薅羊毛的人，薅死了羊」`。「拉闸」「放闸」「回血」这类机械隐喻视为已归化的系统词，**仅限叙述动词**（如「被出口管制拉闸」「官方放闸」）；立档格式（成对标题 / tag / 回链句）自 2026-08-29 起统一用病毒学词系「检出 / 灭活」，见第四节。

例外：首页「战地手记」（记者私话 · OFF THE RECORD）保留人声，不受本表约束。

## 二、正史文风 = 杂志特稿体

**定位**：彭博商业周刊 / 特稿的腔调。长句、白描、不喊金句；反讽与判断**藏在事实的排列顺序里**，把结论留给读者。像一位见过大场面的财经记者在写有时间纵深的特写。

**手感清单**
- 先事实（时间、主体、数字、引语），数字必须可考。
- 用「排列」代替「评论」：把两件事并置，讽刺自己会发生（例：发布会日历 vs 交付日历；天使名单 vs 名人堂花名册）。
- 收束句冷静克制，可以有余味，不可以有感叹号情绪（禁：「太疯狂了！」；可：「署名方式本身，就是一则公告。」）。
- **不做文字交叉引用、不做跨档案时间算术**（2026-08-29 定稿，库内 89 条已全量清理）：正文不写「（见 YYYY-MM-DD 档案）」「另见野史档案」「见该日档案」式指路句，也不写「窗口共 N 天」「N 天 / N 周 / N 个月后」式依赖两条档案日期的计算——档案日期随时可能修订，硬编码的引用与算术会连环过期；关联与窗口跨度一律交给 `series`（前台自动串时间线、自动算天数）。叙事纵深用模糊表述（「随后」「后来」「不久之后」「数日后」）或年级别粗粒度（「三年后」「四年前」——不怕日期微调，且是特稿体的灵魂）。**单一事件内部**的时长（「停机总计 19 天」「持续七十二小时」「24 小时内明码标价」）属报道事实，不受限。
- **禁**：网络梗、口语化短句轰炸、「战地记者按」（那是旧版遗产，正史一律不用）。

**范例 1**（tag: 惊变 · 库内 2026-06-16）
- title：`600 亿美元：全股票收购签约`
- summary：`SpaceX 与 Anysphere 签署合并协议：全股票，隐含股权价值 600 亿美元，风投支持创业公司被并购的历史纪录。福布斯当日写道：这笔交易把一家火箭公司直接拽进了 AI 编程战争的中心。`
- 收束句范式：`从「不就是个套壳」到历史最大并购案，社区用了三年时间换一种语气。`

**范例 2**（tag: 变阵 · 库内 2025-10-29）
- title：`2.0 当天，联创 CTO 离席`
- 手感：全文不评价离职本身，只排列三个事实——发文百余词克制到冷淡、新公司注册早了十五个月、八个月后成为账面亿万富翁。收束句：`最早离席的人，票价一分没少。`

**范例 3**（tag: 故障 · 库内 2026-07-31）
- title：`盛夏故障潮：一个月十起`
- 手感：用状态页硬数据立骨，把「多数故障根源在上游」这个观察摆成事实清单，收在 `三年前野史里那句「不就是个套壳」，此刻被官方状态页用硬数据写下了另一种注脚。`

## 三、野史文风 = 红后终端体

**定位**：假装每条档案都是 RED QUEEN 系统自动吐出的记录单。字段化开头、机器口吻、零形容词；幽默全部藏在冷冰冰的「系统备注」里。与站点的保护伞 / 蜂巢 / 红后视觉一体。

**summary 模板**（60–90 字）：
`<字段词>：<事实>。<第二字段词>：<事实>。系统备注：<一句冷反讽>。`
- 字段词轮换使用，避免整站单调：`现象：` `事项：` `观测：` `情报：` `取证：` `玩法：` `事故：` `战况：` `时序：` `披露：` `核查：` `鉴定：` `处置：` `状态：`
- 「系统备注：」是标志性收尾，多数条目要有；信息挤不下时可省。

**detail 固定三段**：
1. `记录时间 YYYY-MM-DD（或时段）。` + 事象白描（数据、原话、经过——查证过的事实）。
2. 解析 / 核查段：官方口径 vs 场外动作，机制拆解（「成立机制解析」「场外解析进程如下」「口径矛盾记录」等引导语）。
3. `系统备注：` + 冷收束。允许合理演绎与怪话，但立在真事上（例：`额度池一旦可以互相借道，即视为检测到血气。`）。

**机器口吻词库**（酌情取用，别堆砌）：已存档 / 均已入档 / 样本 / 采样 / 取证 / 鉴定 / 判定 / 观测 / 监测 / 本系统不删除记录 / 后续变更将另行立档 / 无损失，无责任方 / 状态标记为存活 / 复现概率不做评估。

**旧版「战地记者按：」一律改写为「系统备注：」**。

**范例 1**（tag: 事故 · 库内 2025-04-14）
- title：`客服单元 Sam：政策系幻觉`
- summary：`现象：切换设备遭强制登出，客服 Sam 答复系「单设备政策、核心安全机制」。核查：政策不存在，Sam 为 AI，答复系幻觉，登出为会话 bug。损失：Reddit 一夜退订潮。处置：创始人道歉退款。`
- 系统备注范式：`一家出售 AI 的公司，被自家 AI 客服的一句幻觉击穿信任。本系统将此事归类为行为艺术，同时列入失控档案——两个分类都对。`

**范例 2**（tag: 造词 · 库内 2026-08-27）
- title：`全员回血：Codex 时刻定名`
- detail 第二段范式（解析进程的「已知 / 传闻 / 推论」三连）：`已知：Pro 及以上账户多出一只按周结算的独立 Bot 额度池。传闻：高级模型的消耗可通过一定手段指到这只池上。推论：官方口中的「Bot 回血」，在封闭频道里翻译成六个字——高级模型回血。`

**范例 3**（tag: 玩梗 · 库内 2026-06-16）
- title：`梗情监测：Cursor to Mars`
- 手感：纯玩梗条也走记录单格式，收尾自嘲：`本条为纯梗情存档，无损失，无责任方，快乐真实。`

## 四、事件线索（series）与「检出 / 灭活」一拆二

套利、漏洞、促销这类**有生命周期**的事件，按「一拆二」惯例立档。术语取病毒学词系，与全站毒株世界观同源：玩法被观测到 = **检出**，玩法被官方废掉 = **灭活**（2026-08-29 定稿，替代旧词「开闸 / 拉闸」；灭活的样本仍留库，正合「本系统不删除记录」）：

1. **检出条**：玩法出现 / 传开的那天。tag 用套利系（套利 / 重套利 / 极限套利）或漏洞系；**不写关闭回链**（关联由 series 承担），玩法仍存活时末段可写 `后续变更将另行立档`。
2. **灭活条**：玩法失效的那天。tag 固定 `灭活`；**不写「检出记录见…」回链，也不写「窗口共 N 天」**——线索时间线与窗口跨度由前台按 series 自动生成。
3. 两条填**同一个 series**（线索名 = 玩法俗称，2–6 字，如 `临期锁额`）。前台自动串联并计算窗口跨度。
4. **标题专用格式**（线索列表里只有日期 + 标题，两行必须讲完整个故事）：
   - 检出：`<线索名>·检出：<玩法关键信息>`，如 `Team 席位差·检出：40 刀拉五只 5x`
   - 灭活：`<线索名>·灭活：<关闭方式或结果>`，如 `临期锁额·灭活：计数器重新走字`、`假焚诀·灭活：两本账合一`（标题同样不带窗口天数）
5. **玩法仍存活、尚无灭活条时**：先不挂 series、标题不带 `·检出` 前缀，但在标题或摘要标注 `（存活）`（库内范例：`伪装观测：编辑器自称 Bot（存活）`）。待灭活发生：新立灭活条，同时回头给检出条挂 series、改题为 `<线索名>·检出：…` 并去掉存活标记——成对才成线索。
6. **可选扩展态**（线索的中间节点，酌情使用）：玩法被削弱但改版存活 → `<线索名>·变异：<变化>`；灭活后死灰复燃 → `<线索名>·复燃：<新玩法>`。

## 五、双线互文（同一事件的一体两面）

同一天、同一份官方消息，正史记官方视角（特稿体），野史记场外视角（红后体），两种文体的温差本身就是叙事。这是本网站的精髓。

**示例：Grok Bot 下放付费全线（2026-08-27，库内真实双线）**
- 正史（tag: 发布）`Grok Bot 下放付费全线`：特稿体记录下放轨迹与「首个产品级整合」的格局意义。
- 野史（tag: 造词）`全员回血：Codex 时刻定名`：红后体记录场外的「已知/传闻/推论」解析链与命名过程，系统备注收尾。
- **互文不靠文字指路**：「另见野史档案」类钩子句已于 2026-08-29 起全站停用——同日正野档案在时间轴上左右并排，互文自然成立；叙述里可以描摹同一时刻的两面（「场外正忙着庆祝回血」），但不写档案指路句。

## 六、查证纪律（再强调）

- 正史每一个精确数字都要有出处；查不到就模糊化（「约」「据公开报道」）。
- 越劲爆的消息越要交叉验证，别把假新闻写成正史。
- 野史的核心事件必须真实存在，演绎只作用于语气和细节（红后体的「机器口吻」不是编造事实的许可证）。
- 你是记者：立场中立，笔下有火，但底线是不造谣。
