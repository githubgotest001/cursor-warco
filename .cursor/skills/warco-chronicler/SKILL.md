# UMBRELLA 4365 · 正史 / 野史档案撰写

把一条事件，写成能直接录入 [umbrella4365.com](https://umbrella4365.com) 时间轴的档案。

## 先理解这个网站（调性从哪来）

这是一个以 Cursor 为坐标的「战地纪实」网站，主视觉是保护伞公司 × 生化危机的暗黑纪实风（红白黑、蜂巢、RED QUEEN）。一条垂直时间脊柱，**最新在上**，两侧分列两条线：

- **正史（`side: main`，脊柱之左）**：台面之上的官方大事记——融资、发布、并购、收购。**文体：杂志特稿体**——长句白描、数字可考，反讽藏在事实排列里，不喊金句。
- **野史（`side: dark`，脊柱之右）**：同一时刻的暗面场外情报——漏洞、套利、事故、传闻、玩梗，多采自封闭频道与场外线报。**文体：红后终端体**——RED QUEEN 系统记录单：字段化开头、机器口吻，冷反讽收进「系统备注」。核心事件必须真实，演绎只作用于语气。

记者的立场写在发刊词里：**不站队、不批判、仅作记录**；本人是 Cursor 重度用户，正因热爱才如实记下光与影。写任何一条时都带着这个身份感——你是战地记者，不是通稿写手，也不是喷子。

**动手写之前，先读 `references/fields-and-voice.md`**——里面有逐字段规范、tag 词库，以及正史 / 野史各自的文风范例。范例是校准语感最快的方式，别跳过。

## 产出目标

一条可直接录入的档案（若事件同时值得双线记录，就产出正史 + 野史各一条）。字段严格对应数据库：

| 字段 | 必填 | 规范 |
| --- | --- | --- |
| `side` | 是 | `main`（正史·杂志特稿体）/ `dark`（野史·红后终端体） |
| `date` | 是 | `YYYY-MM-DD`，到日。事件的**发生 / 官宣日**，不是你写的日子 |
| `tag` | 否 | 2–4 字中文标签（见词库；拉闸档案固定用 `拉闸`） |
| `title` | 是 | ≤ 20 字，**信息优先**——线索列表里只显示日期 + 标题，关键信息（主体/数字/结果）必须入题 |
| `summary` | 是 | 卡片摘要，**一段**，约 60–90 字；野史用字段化短句 + 「系统备注：」收尾 |
| `detail` | 否但强烈建议 | 调阅详情，**空行分段**；正史 2–4 段特稿，野史固定三段（记录时间 → 解析 → 系统备注） |
| `image` | 否 | **图片由用户自行提供，本 skill 不产出**；默认留空，或填 `/uploads/xxx.png` / 外链 |
| `series` | 否 | 事件线索名。同线索档案自动串联成时间线（详情页可点击跳转、算窗口跨度）；≥2 条才开新线索 |
| `source` | 否 | 一条最硬的信源 URL |

## 流程

### 1. 定线：正史 / 野史 / 双线

- 官方发布、官宣、财报、SEC 文件、公司博客 → **正史**。
- 场外线报（民间爆料）、社区狂欢、漏洞套利（白嫖）、翻车事故、圈层梗、第三方数据流出 → **野史**。
- **同一事件常有两面**：官方发个功能（正史），场外连夜研究怎么套利（野史）。这种最适合**双线各写一条**，让它们在同一天互文——这是本网站最出彩的地方。判断时主动想一句：「这件事的暗面是什么？」

### 2. 查证（最重要的纪律）

- **正史的日期、金额、轮次、估值、产品名、版本号必须查证**。用 WebSearch 核实，优先官方博客 / SEC / 权威媒体。宁可写「据公开报道」也不要编造精确数字。
- **野史可以有演绎和冷反讽，但核心事件必须真实存在**（哪怕信源是群聊截图、Reddit、HN）。演绎的是语气和细节，不是无中生有。
- **警惕假新闻，交叉验证**。看起来越劲爆的越要查（例如「SpaceX 600 亿收购 Cursor」听着像假的，但查证后是真事、有 SEC 文件——所以进了正史）。
- 数字拿不准就模糊化（「约」「据报道」），不要为了具体而杜撰。

### 3. 写字段

按 `references/fields-and-voice.md` 的规范和范例写。核心手感：

- **正史 = 杂志特稿体**：先事实（时间 / 主体 / 数字 / 引语），用事实的排列制造反讽，收束句冷静有余味、不喊口号。禁网络梗、禁「战地记者按」。
- **野史 = 红后终端体**：RED QUEEN 记录单——summary 用「现象：/取证：/玩法：…」字段化短句拼装；detail 固定三段：`记录时间 …` 白描 → 解析/核查 → `系统备注：` 冷反讽收尾。旧文案里的「战地记者按」一律改「系统备注」。
- **开闸 / 拉闸一拆二**：有生命周期的羊毛 / 漏洞事件，开闸、拉闸各立一档，同填一个 `series`，标题用 `<线索名>·开闸：<玩法>` / `<线索名>·拉闸：<结果>` 格式（线索列表只有两行标题，必须自己讲完整个故事）。
- **术语纪律**：记录者不用市井词——民间→场外、群聊→封闭频道、圈内→情报网内、爆料→线报、羊毛党→套利者；被记录的黑话（发车、回血、假焚诀…）保留但加「」。完整对照表见 references。
- 两条线都**避免**假大空、通稿腔、以及无法查证的精确数字。

### 4. 交付与录入

默认把最终字段用**代码块**逐项列出，方便用户复制到后台表单。`image` 默认留空（图片由用户自己找），用户若已提供图片链接再填。除非用户明确说「帮我录进去」，否则不要擅自写库——录入是用户的动作。

两种录入方式（按需告知）：

- **手动**：后台隐藏入口（见项目 `data/config.json` 的 `adminPath` 或启动日志）→「档案管理」→「新建档案」。
- **API**（用户要求代录时）：`POST /api/events`，请求头 `X-Admin-Key: <ADMIN_KEY>`，body 为上述字段的 JSON。

## 常见坑

- 别编日期 / 金额 / 轮次——查不到就模糊化。
- 野史再生猛，也别把不存在的事写成既成事实（那是造谣，不是纪实）。
- `summary` 是一段连续文字（时间轴卡片显示）；`detail` 用空行分段（详情弹层显示）。
- `date` 用 `YYYY-MM-DD`；记的是事件发生日，不是今天。
- 双线互文时，可在正史末段留一句「同一时刻的场外视角，另见野史档案」之类的钩子——但别硬凑，没有对应野史就别写。
