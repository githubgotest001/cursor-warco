# UMBRELLA 4365 · 信源侦察与档案搜集

本 skill 是**侦察兵**：负责「找到事件、核实事件、判断值不值得入档」，并产出可直接核查录入的档案草稿。
文案的字段规范与文风**不归本 skill 管**——动笔前必须读 `../warco-chronicler/SKILL.md` 及其 `references/fields-and-voice.md`，按那套规范写。

信源清单与检索配方见本目录 `references/sources.md`（含每个信源的可信级别、用法与已知的坑）。

## 两种模式

| 模式 | 触发条件 | 目标 |
| --- | --- | --- |
| **A · 查缺** | 用户未给日期 / 说「查缺补漏」 | 对照本地库找**历史遗漏**：全时段扫描，重点攻空窗期与断线索 |
| **B · 增量** | 用户给了日期（如「8 月 20 日之后」） | 搜集**该日期之后**的新事件，与本地库去重后立档 |

用户没说清楚时默认 A；说「最近有什么新闻」按 B 处理（日期取库内最新档案日）。

## 工作流

### 1. 刷新镜像并读库（永远第一步）

```powershell
node sync.js pull   # 线上 → 本地：档案 + 刊物 + 补给表全量镜像，引用图片（线上库才是唯一真源）
node -e "const {DatabaseSync}=require('node:sqlite');const db=new DatabaseSync('data/chronicle.db',{readOnly:true});const rows=db.prepare('SELECT id,side,date,tag,title,series,front FROM events ORDER BY date ASC').all();for(const r of rows){console.log([r.id,r.side,r.date,r.tag,r.title,r.series,r.front].join(' | '))};console.log('TOTAL:',rows.length)"
```

- **先 `node sync.js pull` 再读**：本地库只是线上库的只读镜像，pull 保证不基于过期数据做判断（离线/pull 失败时才可直接读旧镜像，并向用户说明镜像时间可能滞后）。
- 库为 WAL 模式，只读打开即可，不要写；**改动回写永远走线上**（后台或 REST API 逐条），不改本地库。
- 如需看某条 detail（判断某事件是否已被「顺带写过」），单独 SELECT 该条。
- 仓库里没有种子数据（seed.js 已退役）——档案数据只存在于线上库与本地镜像两处。
- **顺手看哨兵队列**：`data/sentinel-queue.md` 是信源哨兵（`tools/sentinel.js`，定时轮询 L0/L2 信源）攒下的新信号清单。增量侦察先消化队列里未处理的段落（命中的直接进入查证，不用再盲扫），消化完在该段落标一行「（已消化 YYYY-MM-DD）」。队列不存在说明哨兵还没跑过，正常走检索配方。

### 2. 圈定侦察范围

模式 A 的三个突破口（按性价比排序）：

1. **被引用未立档**：现有档案 detail 里提过、但没有独立档案的事件（如「此前 4 月双方已达成算力合作」「一个月后 iPad 版如约上线」「6 月的 Compile 大会」这类一笔带过的钩子）。这类事件已经过站长间接确认，命中率最高。
2. **空窗期**：时间轴上超过 3–4 周没有任何档案的区间（注意 Cursor 圈新闻密度：2026 年后空 2 周就值得怀疑）。
3. **断线 series**：某个系列（融资阶梯 / 自研模型线 / 火箭并购案 / 定价攻防…）中间缺环的位置。

模式 B：范围就是「给定日期 → 今天」，逐周扫描。

### 3. 扫信源

按 `references/sources.md` 的清单与检索式执行。核心纪律：

- **先官方后三方**：cursor.com/blog、cursor.com/changelog、forum.cursor.com 公告区、status.cursor.com、x.ai/news 是一手事实的地基。
- 三方媒体（TechCrunch / Bloomberg / CNBC / Reuters…）用于补语境、拿数字、找评论。
- 聚合站 / AI 百科（kingy.ai、aiuncovers、miraheze wiki 等）**只作线索索引，不作事实来源**——它们的时间线实测出过错（例：曾把 2.0 GA 和 Composer 2.5 都写成 2026 年 1 月，比官方口径错了数月）。凡从聚合站看到的日期与数字，必须回溯到官方或权威媒体确认。
- 每个候选事件至少发起 1–2 次独立检索交叉验证，别在一个来源上定案。

### 4. 交叉查证（决定生死的一步）

- **两源原则**：正史事实需「官方一手」或「≥2 个独立三方」支撑；野史核心事件必须真实存在，演绎只作用于语气。
- **日期口径**：区分官宣日 / 报道日 / 生效日。产品发布取官方 changelog 或博客日期；爆料传闻取首次公开报道日；并购分「签约日」与「交割日」。同一事件不同来源日期打架时（如 Cursor 侧 7-08 上线 vs x.ai 页 7-16），**两个口径都写进核查要点，让用户定夺**，不要私自抹平。
- **数字**：金额、估值、参数量、百分比逐个找出处；找不到就模糊化（「约」「据报道」），宁可含糊不可编造。
- **越劲爆越要查**：先假设是假的，查到实锤为止。

### 5. 入档价值判定

问四个问题，命中 ≥2 条才立档：

1. 影响面：是否改变产品形态、钱、格局、大批用户的体验？
2. 戏剧性 / 记忆点：一年后还会有人提起吗？
3. 互文性：能否与现有档案连线（伏笔、回收、打脸、轮回）？
4. 双线潜质：这件事有没有官方面 + 场外面（最有价值的档案形态）？

密度控制：changelog 级小更新（x.y.z 修复、单一模型上架、小促销）默认不立档，除非引发了社区事件。宁缺毋滥。

### 6. 双线思考

对每个入选事件问一句：「这件事的暗面 / 台面是什么？」官方发布 → 场外怎么玩坏它；场外线报 → 官方有没有回应。值得的就正野各写一条，让它们同日互文。撰写时遵守 chronicler 的术语纪律（民间→场外、群聊→封闭频道等，见其 fields-and-voice.md）。

### 7. 写文案 → 交付

- 按 warco-chronicler 的字段规范与文风写（先读它的 references）。邻圈事件（Claude Code / Codex / Copilot / Windsurf / 国产工具 / 模型厂商自身的大事）补 `front` 战区代号（可用值见 chronicler 的 fields-and-voice.md；波及 Cursor 用户的事件仍以 Cursor 视角写、front 留空）。
- 全部草稿写入 `drafts/archive-drafts-YYYY-MM-DD.md`（当天日期），格式见下方模板。
- 聊天里给一份**摘要清单**（序号 / 正野 / 日期 / 标题 / 一句话 + 最要紧的核查提示），全文不必重复贴。
- **永远不直接进正册**。录入（发布为正式档案）是用户的动作。两种交付升级（都要用户说了才做）：
  - 用户说「投到收件箱」→ `POST <线上>/api/drafts`（`X-Admin-Key`，字段同档案 + `verify` 核查要点 + `origin: 'scout'`）——草稿态入库，站长在后台「收件箱」逐条审核发布，这仍属「交草稿」不属「录入」。
  - 用户说「帮我录」→ `POST /api/events` 直接发布（见 chronicler skill），慎用。

## 草稿文件格式模板

每条档案用如下结构（`核查要点` 供用户核对，**不录入**数据库）：

```
## NN · 正史|野史 | YYYY-MM-DD | 标签

​```
side:    main|dark
date:    YYYY-MM-DD
tag:     XX
title:   ≤20 字标题
summary: 60–90 字一段
series:  （空）或系列名
source:  一条最硬的 URL
detail:
第一段…

第二段…
​```

核查要点：
- 日期口径 / 单一来源 / 传闻标注 等风险逐条列出
- 与现有档案的冲突点（如有）
```

文件头部注明：生成日期、对照的 DB 条数、正野数量统计。若发现**现有档案**的错漏（日期矛盾、口径打架），在文件末尾附「旧档案疑点」一节，只提醒不改动。

## 常见坑

- 聚合站的时间线错误会连环传染——同一错误出现在多个聚合站不等于两源，要看它们是不是互相抄。
- 论坛帖、X 帖的时间戳注意时区（美西官宣 ≈ 北京时间次日凌晨），与站内既有口径保持一致。
- 模式 B 去重时别只看标题：同一事件的「发布 / 扩容 / 灭活」是不同档案；羊毛 / 漏洞类事件按「检出 / 灭活一拆二」惯例立档——两条同填一个 `series`，标题用 `<线索名>·检出/灭活：<关键信息>` 格式（见 chronicler 的 fields-and-voice.md 第四节，库内范例：`临期锁额`、`Team 席位差`、`假焚诀`；「开闸 / 拉闸」为旧词，已停用于立档格式）。反之，同一事件的多家报道只立一档。
- WebSearch 拿不到的死链 / 反爬页面，换检索词或换信源，不要放弃查证直接写「据传」。
- 别忘了野史侧信源（HN、r/cursor、论坛用户区、封闭频道线报）——正史查官方，野史蹲社区。
