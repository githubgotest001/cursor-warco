# UMBRELLA 4365 · 战报汇编（每周战报）

把一周的档案压缩成五分钟读物。战报是全站的节奏发动机：站内是 `/w/:issue` 周刊页，站外是公众号 / TG / 社区分发的内容单元（分发文案另走 warco-herald）。

## 战报体（文体定义）

- **开篇总评**：2–3 句特稿腔，点出本周的「主战况」——像周刊卷首语，冷静、有余味，不喊。
- **正文区块**：`## ` 小节 + `- ` 条目。每条一到两句，字段化（谁 / 干了什么 / 意味着什么），末尾带档案链接 `[档案 »](/ev/id)`。反讽藏在条目排列里。
- **收尾「下周观察」**：2–4 条待验证的钩子（断供倒计时、传闻中的发布、存活窗口的走向）。观察是观测点，不是预言。
- 术语纪律与站内一致（场外 / 封闭频道 / 检出 / 灭活）；**不写操作教程**，窗口只报状态。

## 固定结构（正文写进 posts.content，渲染语法：空行分段、`## ` 小节、`- ` 列表、`[文字](链接)`）

```
（开篇总评 2–3 句，不带小节标题）

## 本周战况

- 正史野史合计 N 条：正史 X · 野史 Y；主要战线：……

## 正史要点

- ……[档案 »](/ev/id)
-（3–6 条，按重要性不按日期）

## 野史暗面

- ……[档案 »](/ev/id)
-（2–5 条）

## 窗口态势

- 存活：……（检出于 MM.DD，已存活 N 天）[作战室 »](/warroom)
- 灭活：……（存活 N 天后关闭）[线索 »](/s/slug)
-（无变动则写「本周场外静默，无新检出与灭活」）

## 下周观察

- ……
-（2–4 条）
```

## 工作流

1. **拉镜像**：`node sync.js pull`——2026-09-02 起一并镜像刊物 `posts`（含 draft）与补给表 `supply`，本地库即可查往期战报的期号、截稿日与体例，不必再单独请求 `/api/posts`（`data/remote.json` 无密钥时刊物会跳过，那就问用户上期期号）。
2. **定周期**：本地 `posts` 里 `kind='weekly'` 的最大 `issue` 即上期，周期 = 上期截稿次日 → 今天；第一期从最近一个周一起算。期号 = 上期 + 1。查询周期内 `date` 落在区间的全部档案（含 series、front）。窗口态势从作战室口径推导：标题带「（存活）」= 存活；series 内「·灭活」新增 = 本周灭活；模型上下架看 `supply` 的 `status` 与 `updated_at`。
3. **汇编**：按固定结构写。取舍纪律——正史要点挑「改变格局 / 钱 / 大批用户体验」的，changelog 级小事并成一条或不写；野史挑「一年后还会被提起」的。
4. **标题与摘要**：
   - title：`战报 第 N 期 · MM.DD–MM.DD`＋一个副题（本周主战况，≤12 字），如 `战报 第 1 期 · 08.24–08.30 · 断供通牒周`。
   - summary：60–90 字，给索引页与 RSS 用——本周最大的一件事 + 数字概览。
   - date：截稿日（周期最后一天）。
5. **交付**：
   - 默认：全文写入 `drafts/dispatch-NNN.md`，聊天给摘要；站长自己贴进后台「编辑部 → 新建战报」。
   - 用户明确说「帮我录」：`POST <线上>/api/posts`（`X-Admin-Key`，字段 `kind:'weekly', issue, title, summary, content, date, status:'draft'`）——**永远投 draft 态**，发布键只属于站长（后台「编辑部」一键发布）。

## 常见坑

- 战报不是档案复读机：条目要重新压缩成一句话，不是把 summary 原样搬来。
- 不写「本周共 N 天」之类废话；不预告没影的事（「下周观察」只列已有信号的）。
- 周期内档案为零时照常出刊：总评写静默周，区块相应收缩——断更比薄刊伤害大。
- 期号唯一（服务端有约束），撞号说明有旧稿，先查 `/api/posts`。
