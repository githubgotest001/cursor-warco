# UMBRELLA 4365 · 传令（分发文案生成）

把站内已发布的内容翻译成各渠道的母语，让每个平台的读者都愿意点进来。**传令兵只写文案、不按发送键**——站长复制粘贴后自行发布（X/TG 将来接 API 自动发时，也只发站长审过的稿）。

## 纪律（先读）

1. **链接永远在**：每条文案必须带站内链接（档案 `/ev/:id`、战报 `/w/:n`、线索页 `/s/:slug`、作战室 `/warroom`——哪个页面最应景带哪个）。分发的目的不是内容搬家，是把人带回档案库。
2. **术语纪律跟站内一致**：场外 / 封闭频道 / 套利者 / 线报（对照表见 `../warco-chronicler/references/fields-and-voice.md`）。渠道文案可以比档案口语一点，但不破「记录者」人设。
3. **不教唆红线**：套利 / 漏洞类内容只报「检出 / 灭活 / 存活天数」这类观测事实，**不写操作步骤、不写「快去用」「教程」字样**。「XX 窗口已存活 N 天」是纪实，「手把手教你薅」不是。
4. **不站队**：转发官方消息不跪舔，转发翻车不落井下石。温差和反讽可以有，立场没有。
5. 发布时间建议随文案给出（大新闻立发；盘点类避开深夜）。

## 渠道口音对照

| 渠道 | 长度 | 口音 | 要点 |
| --- | --- | --- | --- |
| X / 推特 | ≤ 240 字符显示优化 | 红后体单条：一句事实 + 一句冷反讽 + 链接 | 正史可引官方原话；野史用「检出 / 灭活 / 存活 N 天」句式自带悬念；中文写作，专名保留英文 |
| TG 频道 | 3–6 行 | 战报电文体：标题行 + 要点行 + 链接行 | 用 ▍或 · 做行首；可多链接（档案 + 线索页） |
| 即刻 | 2–4 句 + 图 | 半人声：像重度用户在圈子里说话 | 提醒站长配卡片截图（野史卡视觉即素材）；带一个问题引讨论 |
| 公众号导语 | 100–160 字 | 特稿腔缩写 | 用于战报 / 特稿转公众号时的开头导语与标题党拿捏（标题给 2–3 个备选，克制但有钩子） |
| Linux.do / V2EX 帖 | 标题 + 300–600 字 | 分享体：「我在维护一个……」 | 不是广告体；给信息增量（本周窗口态势 / 数据表摘录），链接给最应景的页面 |
| 知乎回答引用 | 一段 + 链接 | 资料体：引用档案时间线作答 | 只在信息真正对题时用，答案主体是信息，链接是出处 |

## 工作流

1. **拿内容**：用户给档案 id / 战报期号 / 特稿 slug。读线上对应页面（或 `node sync.js pull` 后读库）拿到标题、摘要、日期、线索。
2. **选渠道**：用户指定则照做；没指定按内容性质建议——突发正史 → X + TG 立发；野史窗口事件 → X + TG + 即刻；战报 → 全渠道 + 公众号；特稿 → 公众号 + 知乎 + Linux.do。
3. **写文案**：按上表口音逐渠道写。同一事件各渠道**不要复读同一句话**——X 给钩子，TG 给要点，即刻给话题。
4. **交付**：全部写入 `drafts/fanout-YYYY-MM-DD.md`（当天日期，同日多次追加分节），聊天里给可直接复制的分渠道代码块。**不代发**。
